A mapper converts data by a [type](/language/) in both directions:

- **Denormalization** — external data (decoded JSON, a form, a database row)
  into PHP values: objects, enums, dates, typed lists.
- **Normalization** — PHP values back into plain data (scalars, arrays) ready
  for `json_encode()`.

## Installation

```bash
composer require type-lang/mapper
```

**Requirements:**
* `PHP >= 8.1`

## Usage

```php
$mapper = new TypeLang\Mapper\Mapper();

$array = $mapper->normalize(new Example());
// ['key' => 42, ...]

$object = $mapper->denormalize($array, Example::class);
// object(Example) { key: int(42) }
```

## Guide

### Objects

A class is mapped by its public properties and their native types, nothing
has to be configured:

```php
final class User
{
    public int $id;
    public string $name;
}
```

Data that does not match the class is rejected with the path of the wrong
value:

<Tabs>
<TabItem label="Valid data">
```php
$mapper->denormalize(['id' => 42, 'name' => 'Alice'], User::class);
// User { id: 42, name: 'Alice' }
```
</TabItem>

<TabItem label="Wrong type">
```php
$mapper->denormalize(['id' => 'abc', 'name' => 'Alice'], User::class);
// throws InvalidValueException:
// $.id: Value must be of type int, but "abc" given
```
</TabItem>

<TabItem label="Missing field">
```php
$mapper->denormalize(['id' => 42], User::class);
// throws InvalidValueException: $.name: Required field "name" is missing
```
</TabItem>
</Tabs>

<Aside>
An object is created without calling its constructor. See
[metadata](/mapper/metadata/) for the rules of a class.
</Aside>

### Nested objects

A property of a class type is mapped the same way, to any depth:

```php
final class City
{
    public string $name;
}

final class Trip
{
    public City $from;
}
```

<Tabs>
<TabItem label="Valid data">
```php
$mapper->denormalize(['from' => ['name' => 'Paris']], Trip::class);
// Trip { from: City { name: 'Paris' } }
```
</TabItem>

<TabItem label="Not an object">
```php
$mapper->denormalize(['from' => 'Paris'], Trip::class);
// throws InvalidValueException:
// $.from: Value must be of type object{name: string}, but "Paris" given
```
</TabItem>

<TabItem label="Wrong nested value">
```php
$mapper->denormalize(['from' => ['name' => null]], Trip::class);
// throws InvalidValueException:
// $.from.name: Value must be of type string, but null given
```
</TabItem>
</Tabs>

### Lists

The native `array` says nothing about its elements: such a property takes
any array as it is. The type of the elements is given by `@var`:

```php
final class Route
{
    /**
     * @var list<City>
     */
    public array $stops;
}
```

Both the list and each of its elements are checked:

<Tabs>
<TabItem label="Valid data">
```php
$mapper->denormalize([
    'stops' => [['name' => 'Paris'], ['name' => 'Berlin']],
], Route::class);
// Route { stops: [City { name: 'Paris' }, City { name: 'Berlin' }] }
```
</TabItem>

<TabItem label="Wrong element">
```php
$mapper->denormalize([
    'stops' => [['name' => 'Paris'], 'Berlin'],
], Route::class);
// throws InvalidValueException:
// $.stops[1]: Value must be of type object{name: string},
// but "Berlin" given
```
</TabItem>

<TabItem label="Not a list">
```php
$mapper->denormalize([
    'stops' => ['a' => ['name' => 'Paris']],
], Route::class);
// throws InvalidValueException:
// $.stops: Value must be of type list<object{name: string}>,
// but array(1) given
```
</TabItem>
</Tabs>

<Aside type="caution">
PHPDoc is read only with the `type-lang/phpdoc` package installed. Without
it use the `#[MapType('list<City>')]` attribute, see
[property types](/mapper/metadata/types/).
</Aside>

### Refined types

A PHPDoc type may be stricter than the native one. Any of the
[supported types](/mapper/types/) can be used:

```php
final class User
{
    /**
     * @var positive-int
     */
    public int $id;

    /**
     * @var non-empty-string
     */
    public string $name;
}
```

<Tabs>
<TabItem label="Valid data">
```php
$mapper->denormalize(['id' => 42, 'name' => 'Alice'], User::class);
// User { id: 42, name: 'Alice' }
```
</TabItem>

<TabItem label="Negative id">
```php
$mapper->denormalize(['id' => -1, 'name' => 'Alice'], User::class);
// throws InvalidValueException:
// $.id: Value must be of type positive-int (>= 1)
```
</TabItem>

<TabItem label="Empty name">
```php
$mapper->denormalize(['id' => 42, 'name' => ''], User::class);
// throws InvalidValueException:
// $.name: Value must be of type non-empty-string (non-empty)
```
</TabItem>
</Tabs>

### Optional fields

A property with a default value is optional. A nullable property without a
default one still has to be given:

```php
final class Account
{
    public string $role = 'member';
    public ?string $email;
}
```

<Tabs>
<TabItem label="Without role">
```php
$mapper->denormalize(['email' => null], Account::class);
// Account { role: 'member', email: null }
```
</TabItem>

<TabItem label="Without email">
```php
$mapper->denormalize(['role' => 'admin'], Account::class);
// throws InvalidValueException: $.email: Required field "email" is missing
```
</TabItem>
</Tabs>

### Enums and dates

A backed enum is mapped by its value, a date by a string:

```php
enum Role: string
{
    case Admin = 'admin';
    case Member = 'member';
}

final class Member
{
    public Role $role;
    public DateTimeImmutable $createdAt;
}
```

<Tabs>
<TabItem label="Valid data">
```php
$mapper->denormalize([
    'role' => 'admin',
    'createdAt' => '2026-01-15T10:00:00+00:00',
], Member::class);
// Member {
//   role: Role::Admin,
//   createdAt: DateTimeImmutable('2026-01-15T10:00:00+00:00'),
// }
```
</TabItem>

<TabItem label="Unknown role">
```php
$mapper->denormalize([
    'role' => 'root',
    'createdAt' => '2026-01-15T10:00:00+00:00',
], Member::class);
// throws InvalidValueException:
// $.role: Value must be of type 'admin'|'member', but "root" given
```
</TabItem>
</Tabs>

### Type coercion

A value written in another form is converted when it is the same value,
as in data of a form or a query string. See
[type coercion](/mapper/coercion/) for the rules and the strict mode.

```php
$mapper->denormalize('42', 'int'); // 42

$mapper->denormalize('4.2', 'int');
// throws InvalidValueException: $: Value must be of type int, but "4.2" given
```

### Normalization

`normalize()` converts a value back into plain data by the same types:

```php
$member = $mapper->denormalize([
    'role' => 'admin',
    'createdAt' => '2026-01-15T10:00:00+00:00',
], Member::class);

$mapper->normalize($member);
// ['role' => 'admin', 'createdAt' => '2026-01-15T10:00:00+00:00']
```

<Aside>
The type of `normalize()` is optional: without it a value is
normalized by its own type (an object by its class, an array element by
element).
</Aside>

### Any type

The type is not only a class, but any of the
[supported types](/mapper/types/):

```php
$mapper->denormalize('42', 'int');
// 42

$mapper->denormalize([['id' => 1, 'name' => 'Alice']], 'list<User>');
// [User { id: 1, name: 'Alice' }]

$mapper->denormalize(['page' => '2'], 'array{page: positive-int, size?: int}');
// ['page' => 2]

$mapper->denormalize('auto', 'int|"auto"');
// 'auto'
```

### Checking without exceptions

`isDenormalizable()` and `isNormalizable()` return whether a value can be
converted, without throwing on invalid data:

```php
$mapper->isDenormalizable(['id' => 42, 'name' => 'Alice'], User::class);
// true

$mapper->isDenormalizable(['id' => 'abc', 'name' => 'Alice'], User::class);
// false
```

See [errors](/mapper/errors/) for the exceptions and their messages.
