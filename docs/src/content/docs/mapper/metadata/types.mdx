The type of a property and its strictness.

Every option is shown in each [metadata source](/mapper/metadata/): choose
the tab of the source you use. When a source cannot express an option, its
tab says what is used instead.

## Type

The type of the property: any [supported type](/mapper/types/). When it is
not specified, the native type of the property is used.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\MapType;

final class User
{
    #[MapType('list<non-empty-string>')]
    public array $tags = [];
}
```
</TabItem>

<TabItem label="PHPDoc">
```php
final class User
{
    /**
     * @var list<non-empty-string>
     */
    public array $tags = [];

    /**
     * @param list<non-empty-string> $roles
     */
    public function __construct(
        public array $roles = [],
    ) {}
}
```
</TabItem>

<TabItem label="Reflection">
```php
final class User

```
</TabItem>

</TabItem>

<Tabs syncKey="data">
<TabItem label="Valid data">
```php
$mapper->denormalize(['tags' => ['php', 'mapper']], User::class);
// User { tags: ['php', 'mapper'] }
```
</TabItem>

<TabItem label="Invalid data">
```php
$mapper->denormalize(['tags' => ['php', '']], User::class);
// throws InvalidValueException:
// $.tags[1]: Value must be of type non-empty-string (non-empty)
```
</TabItem>
</Tabs>

<Aside type="tip">
In attributes and PHPDoc names of classes are resolved by the
`use` statements of the file, as in PHP:
`#[MapType('list<Address>')]`. In config files they are fully
qualified.
</Aside>

### Read and write types

Different types for normalization (read) and denormalization (write) are
given by [getters and setters](/mapper/metadata/access/): the `type` of
`#[MapGetter]` and `#[MapSetter]`, the `type` key in `get` and `set`. The
type of a direction without it is the type of its access: the property,
the hook or the method.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\MapGetter;
use TypeLang\Mapper\Mapping\MapSetter;

final class User
{
    #[MapGetter(type: 'int'), MapSetter(type: 'positive-int')]
    public int $id;
}
```
</TabItem>

<TabItem label="PHPDoc">
```php
final class User
{
    private string $value = '';

    public int $id {
        /** @return int */
        #[MapGetter]
        get => (int) $this->value;
        /** @param positive-int $id */
        #[MapSetter]
        set(int $id) {
            $this->value = (string) $id;
        }
    }
}
```
</TabItem>

<TabItem label="Reflection">
```php
final class User
{
    private string $value = '';

    public int $id {
        #[MapGetter]
        get => (int) $this->value;
        #[MapSetter]
        set(int|string $id) {
            $this->value = (string) $id;
        }
    }
}
```
</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'id' => [
                'get' => ['type' => 'int'],
                'set' => ['type' => 'positive-int'],
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "id": {
                "get": { "type": "int" },
                "set": { "type": "positive-int" }
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        id:
            get: { type: int }
            set: { type: positive-int }
```
</TabItem>

<TabItem label="NEON">
```yaml
App\User:
    properties:
        id:
            get: [type: int]
            set: [type: positive-int]
```
</TabItem>

</Tabs>

<Tabs syncKey="data">
<TabItem label="Valid data">
```php
$user = $mapper->denormalize(['id' => '42'], User::class);
$user->id;                 // 42
$mapper->normalize($user); // ['id' => 42]
```
</TabItem>

<TabItem label="Invalid data">
```php
$mapper->denormalize(['id' => -1], User::class);
// throws InvalidValueException:
// $.id: Value must be of type positive-int (>= 1)
```
</TabItem>
</Tabs>

<Aside type="caution">
`#[MapType]` on a property sets both types, on a hook or a method it is an
error. The hooks of a property without `#[MapGetter]` and `#[MapSetter]`
are not called: its value is read and written directly.
</Aside>

## Strict types

Disables [type coercion](/mapper/coercion/) for the value of the property
and its nested values, or enables it with `false`. Overrides the
[configuration option](/mapper/configuration/#strict).
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\MapType;

final class User
{
    #[MapType('int', strict: true)]
    public int $id;
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: the [configuration option](/mapper/configuration/#strict) is used.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'id' => [
                'type' => 'int',
                'strict' => true,
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "id": {
                "type": "int",
                "strict": true
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        id:
            type: int

```
</TabItem>

<TabItem label="NEON">

</TabItem>

</Tabs>
