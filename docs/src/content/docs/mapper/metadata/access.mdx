How a property is read on normalization and written on denormalization. By
default a property with its own value is accessed directly, bypassing its
hooks, and a virtual property through its hooks.

## Methods

A getter takes no required arguments, a setter takes one value, its result
is not used. The type is the return type of the getter and the parameter
type of the setter, `#[MapType]` and PHPDoc of the method override it.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\MapGetter;
use TypeLang\Mapper\Mapping\MapSetter;

final class User
{
    public string $name = '';

    #[MapGetter('name')]
    public function getName(): string
    {
        return \ucfirst($this->name);
    }

    #[MapSetter('name')]
    public function setName(string $name): void
    {
        $this->name = \strtolower($name);
    }
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option. The types are read from
`@return` of the getter and `@param` of the setter.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: the property is accessed directly.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'name' => [
                'getter' => 'getName',
                'setter' => 'setName',
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "name": {
                "getter": "getName",
                "setter": "setName"
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        name:
            getter: getName
            setter: setName
```
</TabItem>

<TabItem label="NEON">
```yaml
App\User:
    properties:
        name:
            getter: getName
            setter: setName
```
</TabItem>

</Tabs>

```php
$user = $mapper->denormalize(['name' => 'JOHN'], User::class);
$user->name;               // 'john'
$mapper->normalize($user); // ['name' => 'John']
```

<Aside>
A missing field gets its default value through the setter.
</Aside>

<Aside type="caution">
The property of the name must be mapped, a public one by default: a
private property behind a getter and a property without a PHP field, such
as a computed `fullName`, are not supported yet.
</Aside>

## Hooks

Accesses a property with its own value through its PHP 8.4 hooks. The type
is the type of the property for the `get` hook and the parameter type of
the `set` hook.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\MapGetter;
use TypeLang\Mapper\Mapping\MapSetter;

final class User
{
    public string $name = '' {
        #[MapGetter]
        get => \ucfirst($this->name);
        #[MapSetter]
        set(string $value) => \strtolower($value);
    }
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: only a virtual property is accessed through
its hooks.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'name' => [
                'getter' => true,
                'setter' => true,
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "name": {
                "getter": true,
                "setter": true
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        name:
            getter: true
            setter: true
```
</TabItem>

<TabItem label="NEON">
```yaml
App\User:
    properties:
        name:
            getter: true
            setter: true
```
</TabItem>

</Tabs>

## One direction

Maps a property in one direction only.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\Direction;
use TypeLang\Mapper\Mapping\MapOnly;

final class User
{
    #[MapOnly(Direction::Normalization)]
    public string $createdAt = '2026-01-01';
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: a virtual property takes part in the
directions it has hooks for.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'createdAt' => [
                'only' => 'normalization',
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "createdAt": {
                "only": "normalization"
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        createdAt:
            only: normalization
```
</TabItem>

<TabItem label="NEON">
```yaml
App\User:
    properties:
        createdAt:
            only: normalization
```
</TabItem>

</Tabs>

```php
$user = $mapper->denormalize(['createdAt' => 'now'], User::class);
$user->createdAt;          // '2026-01-01'
$mapper->normalize($user); // ['createdAt' => '2026-01-01']
```

<Aside type="caution">
A direction left out by one source is not brought back by another one: an
`only` key of the other direction over `#[MapOnly]` is an error.
</Aside>

<Aside>
The field of a property that is only normalized is not an extra one
under the [`rejectExtraFields`](/mapper/configuration/#reject-extra-fields)
option.
</Aside>
