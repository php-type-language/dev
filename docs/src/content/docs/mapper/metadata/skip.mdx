Leaves a field out of the normalized data under a condition. Several
conditions can be combined: the field is skipped when any of them matches.
A condition is given where the read is declared: on a property, on a
[getter or a `get` hook](/mapper/metadata/access/) with `#[MapGetter]`, in
the `get` key of a config.

Every option is shown in each [metadata source](/mapper/metadata/): choose
the tab of the source you use. When a source cannot express an option, its
tab says what is used instead.

## When null
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\SkipWhenNull;

final class User
{
    #[SkipWhenNull]
    public ?string $phone = null;
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: the property is always normalized.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'phone' => [
                'skip' => 'null',
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "phone": {
                "skip": "null"
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        phone:
            skip: 'null'
```
</TabItem>

<TabItem label="NEON">
```yaml
App\User:
    properties:
        phone:
            skip: 'null'
```
</TabItem>

</Tabs>

```php
$mapper->normalize(new User()); // []
```

<Aside type="caution">
In config files the condition is the string `'null'`: an
unquoted `null` of YAML and NEON, and `null` of PHP
and JSON, are not accepted.
</Aside>

## Expression

An expression of the
[Symfony Expression Language](https://symfony.com/doc/current/components/expression_language.html),
`this` is the object, `value` is the value of the property. Requires
`symfony/expression-language`.

- The `context` argument renames `this`: a variable name other than
  `value`.
- An exception, an error, a notice or a warning of the expression, such as
  of a property the object does not have, is a violation of the field.
<Tabs syncKey="metadata">
<TabItem label="Attributes">
```php
use TypeLang\Mapper\Mapping\SkipWhen;

final class User
{
    public bool $isGuest = true;

    #[SkipWhen('this.isGuest')]
    public string $email = 'guest@example.com';
}
```
</TabItem>

<TabItem label="PHPDoc">
<Aside type="caution">
There is no PHPDoc tag for this option.
</Aside>

</TabItem>

<TabItem label="Reflection">
<Aside>
PHP has no such declaration: the property is always normalized.
</Aside>

</TabItem>

<TabItem label="PHP Config">
```php
<?php

return [
    App\User::class => [
        'properties' => [
            'email' => [
                'skip' => 'this.isGuest',
            ],
        ],
    ],
];
```
</TabItem>

<TabItem label="JSON">
```json
{
    "App\\User": {
        "properties": {
            "email": {
                "skip": "this.isGuest"
            }
        }
    }
}
```
</TabItem>

<TabItem label="YAML">
```yaml
App\User:
    properties:
        email:
            skip: this.isGuest
```
</TabItem>

<TabItem label="NEON">
```yaml

```
</TabItem>

</Tabs>

```php

```

### Functions and value

An expression sees the object (`this`), the value of the property
(`value`) and the functions of the language.

```php
use TypeLang\Mapper\Mapping\SkipWhen;

final class User
{
    #[SkipWhen('value === "" or this.age < 18')]
    public string $email = '';

    public int $age = 16;
}
```

```php
$mapper->normalize(new User()); // ['age' => 16]
```

Your own functions are registered in an expression language given to the
mapper. The same language parses the expressions and evaluates them.

```php
use Symfony\Component\ExpressionLanguage\ExpressionLanguage;
use TypeLang\Mapper\Mapper;

$language = new ExpressionLanguage();
$language->register(
    'blank',
    static fn(string $v): string => "($v === '')",
    static fn(array $vars, mixed $v): bool => $v === '',
);

$mapper = new Mapper(expressions: $language);
```

```php
final class User
{
    #[SkipWhen('blank(value)')]
    public string $email = '';
}

$mapper->normalize(new User()); // []
```

<Aside type="caution">
An expression with a function the language does not know is an error of
the metadata. Metadata read by another language, such as one from a cache,
throws `TypeDefinitionException` when the class type is built.
</Aside>
