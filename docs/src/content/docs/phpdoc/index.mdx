Most PHP code keeps part of its types in the docblock: a `@param` narrowing
`array` to `list<User>`, a `@throws` PHP has no syntax for, a `@template`
making a class generic. The PHPDoc component reads such a comment into a
description and a list of tags, each parsed by what the tag means. Types in
the tags are read by the [TypeLang grammar](/language/).

## Installation

```bash
composer require type-lang/phpdoc
```

## Usage

```php
use TypeLang\PhpDoc\DocBlockParser;

$parser = new DocBlockParser();

$block = $parser->parse(<<<'PHPDOC'
    /**
     * Sends a notification to the given recipient.
     *
     * @see Mailer::send() The underlying transport.
     * @return bool
     */
    PHPDOC);

echo $block->description;   // "Sends a notification to the given recipient.\n"
echo count($block);         // 2

foreach ($block as $tag) {
    echo $tag->name;        // "see", "return"
}
```

<Aside>
`new DocBlockParser()` recognizes every built-in tag: the standard set and
the phpDocumentor, Psalm, PHPStan, Phan, PhpStorm and PHP CodeSniffer
families. An empty list of [platforms](/phpdoc/platforms/) recognizes no
tag at all.
</Aside>

## Broken tags do not break the comment

A tag whose body does not match its grammar is returned as an `InvalidTag`
with the reason, the tags around it are parsed as usual. An unknown tag is a
plain `Tag`.

```php
$block = $parser->parse(<<<'PHPDOC'
    /**
     * @param int $wellFormed
     * @param not a valid type here $because
     */
    PHPDOC);

$broken = $block[1];        // InvalidTag
echo $broken->reason->getMessage();
// Malformed "@param" tag, expected: <Type> <Variable> [ <Description> ]
```
