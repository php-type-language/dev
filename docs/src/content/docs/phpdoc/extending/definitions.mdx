A definition turns a `@tag` line into a [tag](/phpdoc/extending/tags/).
There is one per tag, it declares the [grammar](/phpdoc/extending/grammar/)
of the line and creates the tag from what the grammar matched.

The definition of [`@param`](/phpdoc/tags/param/):

```php
final class ParamTagDefinition extends TagDefinition
{
    public function __construct()
    {
        parent::__construct(
            name: 'param',
            // "@param" <Type> <Variable> [ <Description> ]
            spec: Spec::sequence(
                Spec::rule(TypeCombinator::NAME, 'type'),
                Spec::rule(VariableCombinator::NAME, 'variable'),
                Spec::maybe(
                    Spec::rule(DescriptionCombinator::NAME, 'description'),
                ),
            ),
            placement: TagPlacement::Block,
        );
    }

    public function create(string $name, TagPayload $result): ParamTag
    {
        return new ParamTag(
            name: $name,
            statement: $result->get('type'),
            variable: $result->get('variable'),
            description: $result->find('description'),
        );
    }
}
```

| Argument    | Value                                                      |
|-------------|------------------------------------------------------------|
| `name`      | the name of the tag, without the `@`                       |
| `spec`      | the grammar of the line after the name                     |
| `placement` | where the tag may be written, see [below](#inline-tags)    |
| `description` | what the tag means, in markdown, `null` by default       |

The description is for the tools around the parser, such as a language
server showing the meaning of a tag under the cursor:

```php
$parser = new DocBlockParser();

echo $parser->tags->find('param')
    ?->description;
// The `@param` tag documents a single argument of a function or method.
// ...
```

<Aside>
The built-in definitions also have a static `getCanonicalName()`: a
convention to refer to the name without creating the definition, not a part
of `TagDefinitionInterface`.
</Aside>

## Building the tag

`create()` gets a `TagPayload` with the values the grammar
[captured](/phpdoc/extending/grammar/#captures) and returns the tag.

A line that does not match the `spec` never reaches `create()`: it becomes
an [`InvalidTag`](/phpdoc/#broken-tags-do-not-break-the-comment).

## Unknown tags

A tag without a definition is read by `GenericTagDefinition`: the whole
line becomes the description of a plain `Tag`. A `TagFactory` built by hand
takes a `createUnknownTagDefinition` closure to read such tags another way.

## Inline tags

```php
enum TagPlacement
{
    // inside a description: {@tag ...}
    case Inline;
    // on a line of its own
    case Block;
    // both, the default
    case Any;
}
```

| Placement | Built-in tags                                             |
|-----------|-----------------------------------------------------------|
| `Any`     | [`@see`](/phpdoc/tags/see/), [`@link`](/phpdoc/tags/link/), [`@internal`](/phpdoc/tags/internal/), [`@example`](/phpdoc/tags/example/) |
| `Inline`  | [`@inheritdoc`](/phpdoc/tags/inherit-doc/), [`@source`](/phpdoc/tags/source/) |
| `Block`   | every other tag                                           |

An inline tag is parsed into the same tag object as a block one.

<Aside>
The placement is not checked yet: any known tag written as `{@name ...}` is
parsed, whatever its placement.
</Aside>
