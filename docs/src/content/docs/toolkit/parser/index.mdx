The parser component analyzes a [TypeLang](/language/) type declaration
string and builds an AST (Abstract Syntax Tree) out of it, checking the
grammar along the way.

## Installation

```bash
composer require type-lang/parser
```

Requires PHP 8.1 or later.

## Quick start

The `TypeLang\Parser\TypeParser` class is the entry point of the component.
Its `parse()` method turns a type declaration string into a
`TypeLang\Type\TypeNode` instance (a `NamedTypeNode`, `UnionTypeNode`, etc.,
depending on the source).

```php
$parser = new TypeLang\Parser\TypeParser();

$type = $parser->parse('array{key: int}'); // NamedTypeNode

$type->name->toString(); // 'array'
count($type->fields);    // 1
$type->fields->isSealed; // true
```

Every node exposes an `$offset` (byte offset in the source where the node
starts) and, depending on its kind, a handful of other public properties. The
node classes themselves (`TypeLang\Type\*`) belong to the separate
`type-lang/types` package.

<Aside>
If a statement cannot be parsed, `parse()` throws an exception implementing
`TypeLang\Parser\Exception\ParserExceptionInterface`. See
[partial parsing](/toolkit/parser/tolerant-mode/) for a way to read partially valid
input instead of failing outright.
</Aside>

## Three ways of reading a source

`TypeParser` asks the grammar three different questions, all three declared on
`TypeParserInterface`:

- `parse(): TypeNode` is the strict mode. Requires the whole input to be a
  syntactically valid type statement, throws a `ParserExceptionInterface` on
  the first error.
- `partial(): ParsedResult` reads as much of the input as the grammar
  describes and returns a `TypeLang\Parser\Partial\ParsedResult` carrying the
  type built out of the read part and the offset the reading stopped at.
  Useful for docblock parsing, where a type declaration is followed by a
  free-text description. See [tolerant mode](/toolkit/parser/tolerant-mode/).
- `validate(): CheckResult` tells whether the source is a type, building
  nothing of it. This is the cheapest of the three whenever the type itself is
  of no use. See [validation](/toolkit/parser/tolerant-mode/#validation).

## Parser arguments

All three methods accept a string, a resource, an `SplFileInfo` or a
phplrt `ReadableInterface`:

```php
$parser->parse('object{key?: int<0, max>}');
$parser->parse(fopen(__DIR__ . '/source.txt', 'rb'));
$parser->parse(new SplFileInfo(__DIR__ . '/source.txt'));
$parser->parse(Phplrt\Source\FileSource::createFromPathname($pathname));
```

## Parsing other constructs

By default the parser reads a whole type. Two context methods return a new
parser that starts from another grammar rule:

```php
use TypeLang\Parser\TypeParser;

$parser = new TypeParser();

// TypeLang\Type\TypeNode
$type = $parser->forType()->parse('Type<U, V>');

// TypeLang\Type\Template\TemplateParameterNode
$template = $parser->forTemplateParameter()->parse('T of U<V> = Default<Z>');
```

## Errors

Every exception of the parser implements
`TypeLang\Parser\Exception\ParserExceptionInterface`. An error of parsing
also implements `ParserRuntimeExceptionInterface` and tells where the source
is broken:

```php
use TypeLang\Parser\Exception\ParserRuntimeExceptionInterface;

try {
    $parser->parse('array<int, string');
} catch (ParserRuntimeExceptionInterface $e) {
    echo $e->getMessage();     // Invalid template arguments, "," or ">" is expected
    echo $e->position->line;   // 1
    echo $e->position->column; // 18
    echo $e->range->offset;    // 17
}
```

| Property    | Type                | Value                                                        |
|-------------|---------------------|--------------------------------------------------------------|
| `$source`   | `ReadableInterface` | the parsed source                                            |
| `$range`    | `ParsingErrorRange` | `int $offset` and `int $length` of the fragment, in bytes    |
| `$position` | `PositionInterface` | `int $line` and `int $column` of the start of the fragment   |
