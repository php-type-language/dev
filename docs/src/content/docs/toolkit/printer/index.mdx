The printer component is the inverse of the [parser](/toolkit/parser/): where the
parser turns a type string into an AST, the
printer turns that AST back into a string. It walks a
`TypeLang\Type\TypeNode` and renders every node — a union, a shape, a
conditional type — into readable text.

It ships with two printers that render the very same AST differently:

- `TypeLang\Printer\PrettyTypePrinter`: Renders the type as faithfully as possible, preserving every detail the AST carries — shapes, generics, conditional types and all. See [Pretty Printer](/toolkit/printer/pretty/).
- `TypeLang\Printer\NativeTypePrinter`: Renders the closest type PHP itself would accept, collapsing anything without a native equivalent down to a supported approximation. See [Native Printer](/toolkit/printer/native/).

## Installation

```bash
composer require type-lang/printer
```

**Requirements:**
* `PHP >= 8.1`

## Quick start

Every printer implements `TypeLang\Printer\TypePrinterInterface`, a single
`print()` method that takes a `TypeNode` and returns its string form. The AST
usually comes straight from the [parser](/toolkit/parser/), but any hand-built or
rewritten `TypeLang\Type\*` node graph prints just as well.
<Tabs>
<TabItem label="PrettyTypePrinter">
```php
use TypeLang\Parser\TypeParser;
use TypeLang\Printer\PrettyTypePrinter;

$type = new TypeParser()->parse('non-empty-list<positive-int>|null');

echo new PrettyTypePrinter()->print($type);
```

<Aside>
Renders the type exactly as written, only normalizing whitespace.
```
non-empty-list<positive-int>|null
```
</Aside>

</TabItem>

<TabItem label="NativeTypePrinter">
```php
use TypeLang\Parser\TypeParser;
use TypeLang\Printer\NativeTypePrinter;

$type = new TypeParser()->parse('non-empty-list<positive-int>|null');

echo new NativeTypePrinter()->print($type);
```

<Aside>
Collapses everything down to a type PHP would accept: `non-empty-list<…>`
becomes `array`.
```
array|null
```
</Aside>

</TabItem>

</Tabs>

<Aside type="tip">
A printer keeps no state between <code>print()</code> calls and is cheap to
keep around. Construct it once — with whatever formatting options you need —
and reuse the instance across the application rather than building a new one
per type. The only thing that changes after construction is the alias list of
the <code>NativeTypePrinter</code>, through its <code>add*Alias()</code>
methods.
</Aside>

## Choosing a printer

Both printers accept the same AST; they differ only in what they render.

|                        | [Pretty](/toolkit/printer/pretty/) | [Native](/toolkit/printer/native/) |
|------------------------|-----------------------------|-----------------------------|
| **Goal**               | faithful, human-readable    | valid PHP syntax            |
| `array{id: int}`       | `array{id: int}`            | `array`                     |
| `int[]`                | `int[]`                     | `iterable`                  |
| `positive-int`         | `positive-int`              | `int`                       |
| `Foo::BAR`             | `Foo::BAR`                  | `mixed`                     |
| `int<0, max>`          | `int<0, max>`               | `int`                       |
| `$arg is null ? A : B` | `($arg is null ? A : B)`    | `A│B`                       |
| `?int`                 | `?int`                      | `int│null`                  |

Reach for the **pretty** printer to display a type to a human — an error
message, a generated docblock, a diff — where every detail matters. Reach for
the **native** printer to emit something PHP can actually use — a property
type, a parameter hint, generated code.

## Formatting

All formatting is described by a single immutable
`TypeLang\Printer\PrinterOptions` object, which both printers accept. Among
others, it holds:

- `newLine`: The line-break string inserted between the lines of a multi-line rendering. Defaults to `"\n"`.
- `indentation`: The string used for a single indentation level. Defaults to four spaces.

Spacing, nullable and list style, and the number of items that fit one line
are covered in [pretty-printer](/toolkit/printer/pretty/#options).

```php
use TypeLang\Printer\PrettyTypePrinter;
use TypeLang\Printer\PrinterOptions;

$printer = new PrettyTypePrinter(new PrinterOptions(
    newLine: "\r\n",
    indentation: "\t",
));
```

<Aside>
The <code>NativeTypePrinter</code> takes its type aliases as the
<b>first</b> constructor argument and the options as the <b>second</b>, so
pass them by name — see <a href="/toolkit/printer/native/">Native Printer</a>.
</Aside>

## Error handling

A printer renders the node classes it has a node printer for. A node of any
other class, such as a hand-written subclass of your own, makes it throw a
`TypeLang\Printer\Exception\NonPrintableNodeException`.

```php
try {
    echo $printer->print($node);
} catch (\TypeLang\Printer\Exception\PrinterExceptionInterface $e) {
    // Every exception thrown while printing implements this interface.
}
```

Invalid `PrinterOptions`, such as a negative `maxInline*` limit, are rejected
by its constructor with a plain `\InvalidArgumentException`.

An AST produced by the [parser](/toolkit/parser/) is always printable, so this only
becomes a concern when constructing or rewriting the node graph by hand.
